# 故障排查

## 分析结果为空

按顺序检查：

### 1. 是否选了其他程序？

```text
POST /api/analyses {"sourceId": 1, "peerSourceIds": []}
→ 400 {"error":"请至少选择一个要扫描的其他程序"}
```

只选被改动的程序本身不算——自身影响不在扫描范围内。

### 2. 本次是否真的有契约变更？

如果只改了内部实现（变量重命名、提取私有方法），没有触及任何契约，
那么对其他程序确实没有影响。看报告里的「变更清单」确认识别到了什么。

### 3. 对方是否真的在用这个契约？

看该 peer 条目的 `matches`：

```json
{ "matches": [], "impacts": [], "note": null }
```

`matches` 为空说明没有找到使用点。常见原因：

- 对方调用的是动态拼接的 URL（`baseUrl + path`），静态扫不到
- 对方通过反射或脚本调用，不是 Java 代码
- 表名/配置 key 拼写不同（大小写、下划线 vs 驼峰）

## 对方程序读取失败

```json
{ "peerSourceName": "order-service", "note": "无法读取该程序：目录不存在：/path" }
```

只有该条目失败，其他 peer 不受影响。检查位置是否可达、Git 凭据是否配置。

## 定时扫描不触发

### 确认配置生效

```bash
curl http://127.0.0.1:9996/api/schedule | python3 -m json.tool
```

`enabled` 必须是 `true`。注意 cron 是**六段式**（秒 分 时 日 月 周），
五段式会被解析成错误时间。

### 确认程序被正确跳过还是漏掉了

看 `last.details`：

| outcome | reason | 含义 |
|---|---|---|
| `SCANNED` | 有新提交 abc123 → def456 | 正常 |
| `SKIPPED` | 没有新提交 | 正常 |
| `SKIPPED` | 已有分析在进行中 | 上一次还没跑完 |
| `SKIPPED` | 位置不可访问：/path | 目录被删或移动 |
| `SKIPPED` | 没有其他程序可比较 | 只注册了一个程序 |
| `FAILED` | ... | 见对应错误 |

### 手动触发验证

```bash
curl -X POST http://127.0.0.1:9996/api/schedule/run
# 然后轮询
watch -n5 'curl -s http://127.0.0.1:9996/api/schedule | python3 -c "import json,sys; d=json.load(sys.stdin); print(d[\"running\"], d[\"last\"][\"status\"])"'
```

## 接口很慢或超时

### /api/analyses 慢

历史报告可能有几 MB（完整 JSON）。列表查询**不应该**读取报告内容。
如果这一项变慢，检查 `Store.analyses()` 是否用了 `SELECT *`——那会把所有 report_json 都读出来。

### 扫描一直 RUNNING

完整扫描要 fetch 远程仓库（每个可能几十秒）。4 个程序 2~3 分钟是正常的。
超过 10 分钟仍然 RUNNING，可能是网络卡住：

```bash
# 看是否卡在 fetch
tail -50 code-association.log | grep -i fetch
```

强制恢复：重启服务，启动时会把孤儿任务标记为失败。

## 服务无响应但进程还在

典型症状：`/api/health` 正常，但静态资源请求挂住，日志里有
`ClassNotFoundException: ch.qos.logback...`。

原因：运行中的 JVM 打开了 `target/code-association.jar`，而这个 jar 被
`mvn package` 就地覆盖了。重启即可恢复。

**预防**：不要对着正在运行的实例执行 `mvn package`。构建到别的目录，或先停服务。

## 端口被占用

```bash
lsof -nP -iTCP:9996 -sTCP:LISTEN
./stop.sh        # 会等到端口真正释放才退出
./start.sh
```

`stop.sh` 会等待优雅关闭完成（最多 10 秒），避免紧接着启动撞端口。

## 深色模式下图表颜色不对

依赖图（Cytoscape）把颜色烘进画布，无法继承 CSS 变量。
主题切换时 `app.js` 会读取令牌计算值并重建图实例。如果颜色没更新，硬刷新一次页面。

## 还想定位更细

```bash
# 分析进度（阶段 + 百分比 + 当前文件）
curl -s 'http://127.0.0.1:9996/api/analyses?limit=1' | python3 -m json.tool | grep -A3 progress

# 完整报告
curl -s 'http://127.0.0.1:9996/api/analyses/42/report' | python3 -m json.tool | head -80
```

报告里的 `blindSpots` 列出所有解析失败的调用点——"为什么没找到影响"的答案常在这里。
