# 快速上手

## 环境要求

| 依赖 | 版本 | 说明 |
|---|---|---|
| JDK | 21+ | 使用 Java 21 语法（record / sealed / pattern matching） |
| Maven | 3.9+ | 构建 |
| 操作系统 | Linux / macOS / Windows | 三个平台各有对应的启停脚本 |

不需要数据库服务：元数据存本地 SQLite（首次启动自动创建）。

## 三种启动方式

### 1. 下载发布包（推荐）

**Linux / macOS**

```bash
curl -LO https://github.com/geek-xin/code-association/releases/latest/download/code-association-0.3.0.tar.gz
tar -xzf code-association-0.3.0.tar.gz
cd code-association-0.3.0

./start.sh          # 默认 9996 端口
./start.sh 8080     # 指定端口
./stop.sh           # 停止
```

**Windows**：下载 `code-association-0.3.0.zip` 解压（用 Windows 自带解压，保留 CRLF），然后：

```bat
start.bat           :: 默认 9996 端口
start.bat 8080      :: 指定端口
stop.bat            :: 停止
```

`start.bat` 内部带 `-ExecutionPolicy Bypass` 调用 `start.ps1`，不需要改系统执行策略。

`start.sh` 会把进程从当前 shell 完全脱离（PPID=1、独立进程组），关掉终端不会带走服务；
Windows 上 `start.ps1` 以隐藏窗口后台启动。两者都把日志写到
`code-association.log`、PID 写到 `.code-association.pid`（Windows 额外有
`code-association.err.log` 收 stderr）。

> `start.sh` 不硬依赖 `python3` / `lsof` / `curl`：Linux 优先 `setsid` 脱离终端，
> macOS 用 `python3` 双 fork，两者都没有时退化为 `nohup` 并提示；健康检查优先 `curl`，
> 否则用 bash `/dev/tcp`。详见 [INSTALL.md](https://github.com/geek-xin/code-association)。

### 2. 从源码构建

```bash
git clone git@github.com:geek-xin/code-association.git
cd code-association
mvn -q -DskipTests package
./start.sh          # Windows: start.bat
```

### 3. 前台运行（调试用，三平台通用）

```bash
java -jar target/code-association.jar --server.port=9996
```

## 跑通第一次分析

1. 打开 <http://127.0.0.1:9996>
2. 左侧「代码源」→ 添加**两个**程序：
   - 一个是被改动的程序（例如 `order-service`）
   - 一个是可能被波及的程序（例如 `user-service`）
3. 右上角「新建分析」→ 选择被改动的程序
4. 在弹窗底部勾选「同时比较其他程序」→ 选中另一个程序
5. 「开始分析」

> **为什么必须选两个？** 扫描范围只有其他程序。只选一个时没有对比对象，
> 报告里不会有任何影响条目——这是设计如此，不是 bug。

## 第一次该看什么

分析完成后，总览页会出现「对其他程序的影响」卡片：

```text
peer-b  git  1 个契约命中  影响 2 处
  命中的契约
    API   GET /api/users → com.example.order.UserClient#fetchUser(Long)
          HTTP client /api/users/ · order/UserClient.java:11 · 置信度 90%
  受影响的其他程序代码
    UserClient#fetchUser   [高]  risk 66
    OrderService#canOrder  [高]  risk 66  （深度 2，经对方内部调用链传播）
```

读法：**契约**是两边共享的东西，**使用点**是对方代码里真正用到它的位置，
后面的条目是影响在对方程序内部继续传播的结果。

## 验证安装是否正常

```bash
curl http://127.0.0.1:9996/api/health
# {"status":"ok","dataDir":".../.code-association","maxDepth":8,"maxFiles":20000,"aiEnabled":false}

curl http://127.0.0.1:9996/api/schedule
# {"enabled":true,"cron":"0 30 2 * * *",...}
```
