# 界面实现映射

本文是 [界面规范](界面规范) 的**落地层**：规范回答"应该怎样"，本文回答"这件事写在哪个文件的哪一段"。

> 规范与本文配套。改了界面就同时改这两份；`UiContractTest` 会校验本文提到的令牌与类名
> 是否真的在代码里。

### 2.2 深色块未覆盖的令牌

`:root[data-theme="dark"]` 定义了 98 个变量，浅色块 109 个。**未覆盖的 11 个全部不是颜色**：

| 令牌 | 类别 | 为什么不需要覆盖 |
|---|---|---|
| `--r-card` `--r-tile` `--r-control` `--r-pill` | 几何 | 圆角与主题无关 |
| `--ease` `--t-fast` `--t-base` | 动效 | 手感与主题无关 |
| `--sidebar-w` `--sidebar-w-collapsed` | 布局 | 尺寸与主题无关 |
| `--font` `--mono` | 字体 | 字体栈与主题无关 |

**结论：深色块零颜色遗漏，且没有引入浅色不存在的变量**（`dark \ light = ∅`）。
这正是规范 2.1 那条纪律的直接验证：深色只换颜色，不动布局。

### 2.3 声明了但没有 CSS 引用的令牌

| 令牌 | 状态 |
|---|---|
| `--app-bg-tint` `--nav-bg` `--text-inverse` `--neutral` | **真死引用**（浅深两套都定义，全仓零引用） |
| `--map-edge` `--map-arrow` `--map-edge-label` `--map-label-bg` | **canvas 专用**：CSS 不引用，由 `themeColor()` 读取 |

## 5. 数据契约

前端只通过 `api(path, options)` 访问后端：统一前缀 `/api`、
非 2xx 抛 `Error`（优先取响应体 `error` 字段）、204 返回 `null`。

### 5.1 端点

| 端点 | 驱动 |
|---|---|
| `GET /api/health` | 设置页服务状态 |
| `GET/POST/PUT/DELETE /api/sources` | 代码源列表与增删改 |
| `GET /api/sources/{id}/refs` | 分支 / 标签下拉 |
| `GET /api/sources/{id}/commits` | 提交选择列表。参数全部可选：`ref`（分支）、`base` + `target`（限定区间；界面不再使用）、`limit`（默认 30、上限 500，界面用 100）、`since` / `until`（`yyyy-MM-dd`，含两端，按提交时间）。响应 `commits` `count` `ref` `base` `target` `since` `until` `more` `note`：`more=true` 表示还有更早的匹配提交；坏日期与「起始晚于结束」仍是 HTTP 200 + `note`，不进错误态 |
| `GET /api/sources/export` / `POST /api/sources/import` | 导入导出卡片 |
| `GET /api/tags` | 侧栏分组与标签候选 |
| `GET /api/analyses` / `/api/analyses/{id}` | 历史、报告、进度 |
| `GET /api/peers` | 对比程序多选 |

## 6. 样式加载顺序与首帧

```text
index.html <head>
  1. <meta charset> / <meta viewport>
  2. <title>
  3. <link rel="icon">
  4. preconnect fonts.googleapis / fonts.gstatic
  5. <link> Inter 400;500;550;600;700
  6. <script> 内联：读 ca.theme → 解析 system → 写 data-theme / data-theme-pref
  7. <link rel="stylesheet" href="/style.css">
```

**第 6 步必须在第 7 步之前**，否则深色会话会先画一帧白底再变深。这是规范 2.2 的硬约束，
`UiContractTest` 会校验这个顺序。

字体是**外链**，因此：

- 必须保留系统字体兜底（`--font` 栈里的 `-apple-system` / `PingFang SC` / `Microsoft YaHei`）；
- 离线环境下界面仍然可用，只是字形回退；
- `font-weight: 650` 这类未加载的档位由浏览器合成，应避免（见规范第 13 章 #13）。

## 7. 变更检查表

改界面的最小闭环是四处同改，加一次验证：

- [ ] `index.html`：骨架或静态节点
- [ ] `style.css`：令牌（如需新增）与组件规则
- [ ] `app.js`：渲染与交互
- [ ] `docs/wiki/界面规范.md`：规范本身（新增组件要补第 7 章）
- [ ] `docs/wiki/界面实现映射.md`：本文（新增组件补第 3 章，新增行为补第 4 章）
- [ ] `mvn test`（含 `UiContractTest`）

**改完自检**：按规范第 12 章的验收清单逐条过一遍。如果改动修掉了规范第 13 章里的某条偏差，
记得在同一次提交里删掉那一行。
